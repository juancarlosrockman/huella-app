HUELLA — configuración de Cloudflare D1 (beta de pruebas)

La base D1 existente es huella-db. Su ID ya está incorporado en wrangler.jsonc.

IMPORTANTE: esta beta NO tiene autenticación real. El identificador de dispositivo es pseudónimo y no protege un diario privado. No usar con datos sensibles ni abrir al público todavía.

PASOS
1. Esta versión actualiza Wrangler a la rama 4 (mínimo 4.20.0) porque run_worker_first con rutas requiere esa versión. Reemplaza los archivos del proyecto por los de este ZIP. No modifiques el proyecto JC Fútbol Coach.
2. En Cloudflare > Workers & Pages > huella-app > Settings > Bindings, confirma que exista una sola vinculación D1: nombre DB, valor huella-db. Ya está configurada según la revisión anterior.
3. En Settings > Builds, conserva Build command: npm run build. Cambia temporalmente Deploy command a:
   npx wrangler d1 execute huella-db --remote --file=./schema.sql --yes && npx wrangler deploy
   Esto aplica schema.sql a la base remota y luego publica el Worker. Requiere que el entorno de despliegue tenga permisos de Wrangler para editar D1 y desplegar Workers. Si falla por permisos, no repitas ni borres nada: copia el error exacto.
4. Espera a que el despliegue termine correctamente.
5. Abre la URL estable del Worker seguida de /api/health. Debe responder JSON, no la pantalla de la app, e indicar databaseConfigured:true y databaseReady:true.
6. Solo después probaremos guardar/listar acciones y confirmar las tablas.

ALCANCE ACTUAL
Implementado en esta beta: API D1 de acciones por identificador aleatorio de dispositivo, contador básico y esquema SQL.
Pendiente: autenticación real/cuentas, protección robusta del diario, testimonios y moderación funcional, sincronización offline, exportación/eliminación de cuenta y modo católico funcional.
No considerar producción segura hasta completar y probar esas partes.
